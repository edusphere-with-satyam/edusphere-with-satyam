Understanding Queries

A database may contain hundreds or thousands of records. Sometimes, we do not need to see all the records. We may need only specific information, such as students who scored more than 80 marks or students belonging to Class 10.

Formal Definition:
A query is a request made to a database to retrieve specific information from one or more tables according to given conditions.
Simple Definition:
A query is a question or request that we give to a database to get the information we need.

In LibreOffice Base, queries help us search, filter, sort and retrieve required information without changing the original data stored in a table.

📌 Example – Understanding a Query

Suppose the Students table contains:

  • Student_ID
  • Name
  • Class
  • Section
  • Marks

If we want to find only students who scored more than 80 marks, we can create a query using the condition:

Marks > 80

The query will display only the records that satisfy this condition.

How a Query Works

A query generally works with the data stored in a table. We select the table and fields that contain the required information and then specify conditions if necessary.

Basic process:

Table → Select Fields → Apply Criteria → Run Query → Required Results

A query does not normally create a separate copy of the original records. It displays information from the existing database according to the instructions given in the query.

📌 Example – Query Process

Suppose the Students table contains 50 students.

You want to display only the names and marks of students scoring above 80.

You can select Name and Marks as fields and use Marks > 80 as the criterion.

When the query is executed, only matching information is displayed.

Uses of Queries

Queries are useful for several database operations, such as:

  • Finding specific records.
  • Filtering unwanted records from the displayed results.
  • Displaying selected fields from a table.
  • Finding records according to conditions.
  • Sorting the retrieved information.
  • Preparing specific information for reports.
  • Working efficiently with large amounts of data.
📌 Real-Life Example

A school database may contain information about 1,000 students. The school may want to find:

  • Students of Class 10.
  • Students who scored more than 80 marks.
  • Students belonging to Section A.
  • Students whose marks are below 50.

Instead of manually searching through all records, suitable queries can retrieve the required information quickly.

Query Criteria

Formal Definition:
A criterion is a condition specified in a query that determines which records should be included in the query result.
Simple Definition:
A criterion tells the database which records we want to see.

Criteria are particularly useful when a table contains many records. Instead of displaying everything, the query displays only records satisfying the specified condition.

Common Criteria

  • Marks > 80 – marks greater than 80
  • Marks < 50 – marks less than 50
  • Marks = 75 – marks equal to 75
  • Class = 10 – students of Class 10
  • Section = "A" – students of Section A
🔎 Comparison Operators
  • = Equal to
  • > Greater than
  • < Less than
  • >= Greater than or equal to
  • <= Less than or equal to
  • <> Not equal to
🛠️ Practical Steps – Using Criteria in a Query
  1. Open the required database in LibreOffice Base.
  2. Select Queries.
  3. Open the query in Design View or use the Query Wizard.
  4. Select the required table.
  5. Select the field on which you want to apply a condition.
  6. Enter the required criterion.
  7. Run the query.
  8. Check whether the displayed records satisfy the condition.

Query Wizard

Formal Definition:
Query Wizard is a guided tool in LibreOffice Base that helps users create a query by selecting tables, fields, sorting options and criteria step by step.
Simple Definition:
Query Wizard helps beginners create a query without having to manually design every part of it.

It is especially useful for beginners because it provides a sequence of steps for creating a query.

Basic Functions of Query Wizard

  • Select the table or data source.
  • Select the fields to display.
  • Set sorting options.
  • Set search conditions or criteria.
  • Review the query.
  • Save the query with a suitable name.
🛠️ Practical Steps – Creating a Query Using Query Wizard
  1. Open your database in LibreOffice Base.
  2. Select Queries.
  3. Choose Use Wizard to Create Query.
  4. Select the required table.
  5. Select the fields you want to display.
  6. Choose sorting options if required.
  7. Enter criteria if required.
  8. Review the selected options.
  9. Give the query a meaningful name.
  10. Finish the wizard and run the query.

Query Design

Query Design provides more control over the creation of a query. Instead of following only a fixed sequence, the user can select fields, arrange them and specify conditions according to the requirement.

Query Design: A method of creating and modifying a query by specifying its tables, fields, sorting and criteria.
🛠️ Practical Steps – Creating a Query in Design View
  1. Open the database.
  2. Select Queries.
  3. Choose Create Query in Design View.
  4. Select the required table.
  5. Add the required fields to the query.
  6. Specify sorting if needed.
  7. Enter criteria in the appropriate field.
  8. Run the query to see the result.
  9. Save the query with a meaningful name.

Practical – Creating a Simple Query

We will use the Students table created in Session 1. Suppose the table contains Student_ID, Name, Class, Section and Marks.

Our requirement is to display the Name, Class and Marks of students who scored more than 80.

🛠️ Practical Steps – Students Scoring More Than 80
  1. Open SchoolDatabase.
  2. Select Queries.
  3. Choose Create Query in Design View.
  4. Select the Students table.
  5. Add the fields Name, Class and Marks.
  6. In the criteria row under Marks, enter >80.
  7. Run the query.
  8. Only students having marks greater than 80 should appear.
  9. Save the query, for example, as HighScorers.
📌 Expected Result

If the table contains students with marks 92, 85, 76 and 64, the query will display only the records having 92 and 85.

Sorting Query Results

Sorting means arranging the query results in a particular order. Data can generally be arranged in ascending or descending order.

Ascending Order: Data is arranged from smaller to larger values or alphabetically from A to Z.
Descending Order: Data is arranged from larger to smaller values or alphabetically from Z to A.
📌 Example – Sorting Marks

If marks are: 65, 90, 45, 78

Ascending order: 45, 65, 78, 90

Descending order: 90, 78, 65, 45

🛠️ Practical Steps – Sorting Query Results
  1. Open the query in Design View.
  2. Select the field according to which you want to sort.
  3. Choose Ascending or Descending.
  4. Run the query.
  5. Check the order of the displayed results.

Running and Saving a Query

After designing a query, it must be executed to display the required results. If the query may be used again, it should be saved with a meaningful name.

🛠️ Practical Steps – Run and Save a Query
  1. Open or create the query.
  2. Check the selected fields and criteria.
  3. Run the query.
  4. Verify the result.
  5. Save the query.
  6. Give it a meaningful name such as HighScorers.
Tip: Use meaningful query names. A name such as StudentsAbove80 makes the purpose of the query easy to understand.

Query vs Table

Table Query
Stores the actual data. Retrieves or displays required data.
Contains fields and records. Uses fields, conditions and sorting to obtain results.
Main storage object. Information retrieval object.
Can contain all records. Can display only selected records.

Common Practical Mistakes

  • Selecting the wrong table.
  • Selecting an incorrect field.
  • Entering an incorrect criterion.
  • Using text and number criteria incorrectly.
  • Forgetting to run the query.
  • Saving a query with an unclear name.
  • Changing the table when the intention is only to retrieve data.
Important: A query is used to retrieve information according to requirements. Be careful not to accidentally modify the original table while working with database objects.
