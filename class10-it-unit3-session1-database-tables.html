Introduction to Database

In our daily life, we deal with a large amount of data. A school has information about students, teachers, classes, attendance and marks. A bank has information about customers, accounts and transactions. A hospital has information about patients, doctors, medicines and appointments.

If all this information is kept without proper organisation, it becomes difficult to search, update and manage it. A database provides an organised way to store related data so that it can be accessed and managed efficiently.

Formal Definition – Data:
Data refers to raw facts and figures that can be recorded, stored and processed. Data by itself may not provide complete meaning until it is organised or processed.
In simple words:
Data means basic facts such as a person's name, age, roll number, marks, phone number or address.
Formal Definition – Information:
Information is meaningful and useful data obtained after data has been organised, processed or interpreted.
In simple words:
When raw data is arranged or processed in a meaningful way, it becomes information.
Example: Data and Information

Suppose we have the following marks:

75, 82, 91, 68, 84

These numbers are data. If we organise them as the marks of particular students and calculate the average marks, highest marks and lowest marks, the result becomes useful information.

Formal Definition – Database:
A database is an organised collection of related data that is stored in a structured manner so that the data can be easily accessed, managed, updated and retrieved.
In simple words:
A database is an organised place where related information is stored so that we can easily find and manage it.
Example:
A school database may store Student ID, Student Name, Class, Section, Date of Birth, Contact Number and Marks of students.

Why Do We Need a Database?

Imagine that a school has information about 2,000 students written in different notebooks and separate files. If a teacher wants to find the details of one particular student, it may take a lot of time.

A database solves this problem by storing related information in an organised structure. It allows users to find, add, modify and manage information more efficiently.

Major Uses of a Database

  • Storing large amounts of related data.
  • Finding required information quickly.
  • Adding new information.
  • Updating existing information.
  • Deleting information that is no longer required.
  • Organising data systematically.
  • Preparing useful information from stored data.
Example: School Database

A school can maintain a database containing student information. For example:

Student ID Name Class Section Marks
101 Rahul 10 A 78
102 Priya 10 A 86
103 Aman 10 B 91

From this database, the school can search for a particular student, update marks, add new students and retrieve required information.

Database Management System (DBMS)

Simply storing data is not enough when the amount of information becomes large. We also need software that can create databases, store data, retrieve information, modify records and manage the database.

This is where a Database Management System is used.

Formal Definition – DBMS:
A Database Management System (DBMS) is software that enables users to create, store, organise, retrieve, update and manage data in databases.
In simple words:
A DBMS is software that helps us create and manage databases and the data stored inside them.

What Can a DBMS Do?

  • Create a database.
  • Store data in an organised manner.
  • Retrieve required data.
  • Insert new records.
  • Update existing records.
  • Delete unwanted records.
  • Search for specific information.
  • Help users manage database objects.
Example: How a DBMS Helps a School

Suppose a school wants to maintain student records.

Using a DBMS, the school can create a database, create a student table, enter student records, search for a particular student, update a student's information and generate useful reports.

Without proper database software, managing thousands of records would be much more difficult.

Database and DBMS – Difference

Database DBMS
An organised collection of related data. Software used to manage the database.
Contains the stored data. Provides tools to create, access and manage data.
Example: Student records stored in a database. Example: LibreOffice Base used to manage the database.
Remember:
Database = organised data
DBMS = software used to manage that data

Database Objects

A database is not simply a single collection of random data. It contains different objects that help us store, retrieve, enter and present data.

Database Object Main Purpose
Table Stores data in rows and columns.
Query Retrieves specific information from one or more tables.
Form Provides a convenient interface for entering and viewing data.
Report Presents database information in an organised and readable format.
Example: How Database Objects Work Together

Suppose a school has a database containing student records.

  • Table: Stores student information such as ID, name, class and marks.
  • Query: Finds students who scored more than 80 marks.
  • Form: Provides an easier screen for entering student information.
  • Report: Presents the student information in a properly organised format for viewing or printing.

Therefore, these objects perform different tasks but work with the same database information.

Understanding a Table

A table is one of the most important objects in a database. It is used to store related data in a structured form.

Formal Definition – Table:
A table is a database object that stores related data in rows and columns.
In simple words:
A table is like an organised grid in which related information is stored using columns and rows.

Example of a Student Table

Student_ID Name Class Section Marks
101 Rahul 10 A 78
102 Priya 10 A 86
103 Aman 10 B 91

In this table, each column represents a particular type of information, while each row represents the complete information of one student.

Field

Formal Definition – Field:
A field is a named column in a database table that represents a particular type or category of information about the records.
In simple words:
A field tells us what type of information is stored in a column.

For example, in a student table, Student_ID, Name, Class, Section and Marks can be fields.

Field Name What It Stores
Student_ID Unique identification number
Name Student's name
Class Class of the student
Section Section of the student
Marks Marks obtained

Record

Formal Definition – Record:
A record is a complete set of related field values representing one particular item or entity in a database table.
In simple words:
A record is one complete row of information in a table.

In the student table, the information of Rahul forms one record. The information of Priya forms another record.

Example: Understanding a Record

Consider this row:

Student_ID Name Class Section Marks
101 Rahul 10 A 78

The complete row represents one student's information. Therefore, it is one record.

Field vs Record

Field Record
A field represents one category of information. A record represents complete information about one item.
Usually represented by a column. Usually represented by a row.
Example: Name Example: 101, Rahul, 10, A, 78
Easy way to remember:
Column → Field
Row → Record

Data Types

A database contains different kinds of information. A person's name is different from their age, a date is different from a number, and a Yes/No value is different from ordinary text.

Therefore, while creating a table, we need to specify the type of data that a field will store. This is called the data type of the field.

Formal Definition – Data Type:
A data type specifies the kind of value that can be stored in a particular database field.
In simple words:
A data type tells the database what kind of data a field is expected to contain.

Common Data Types

Data Type Example Suitable Use
Text Satyam Names, addresses and other text
Integer 25 Whole numbers
Decimal 85.50 Numbers containing decimal values
Date 04/09/2026 Dates
Time 10:30 AM Time values
Date & Time 04/09/2026 10:30 AM Date and time together
Boolean / Yes-No Yes / No Values with two logical choices
Why is choosing the correct data type important?
Selecting an appropriate data type helps the database understand how the data should be stored and handled. An unsuitable data type can create problems while entering, searching, sorting or calculating data.

Primary Key

When a table contains many records, we need a reliable way to identify each record uniquely. This is where a primary key becomes important.

Formal Definition – Primary Key:
A primary key is a field, or combination of fields, that uniquely identifies each record in a database table.
In simple words:
A primary key is a field whose value is different for every record and helps identify each record uniquely.

Why is a Primary Key Important?

  • It uniquely identifies records.
  • It prevents duplicate identification values.
  • It helps distinguish one record from another.
  • It provides a reliable way to identify a particular record.
Example: Student ID as Primary Key
Student_ID Name Class
101 Rahul 10
102 Priya 10
103 Aman 10

Here, Student_ID can be used as a primary key because each student has a different ID.

Even if two students have the same name, their Student_ID can still uniquely identify them.

Characteristics of a Good Primary Key

  • It should uniquely identify each record.
  • It should not contain duplicate values.
  • It should provide a reliable identification of the record.
  • It should be chosen carefully according to the purpose of the table.
Important:
A primary key is not simply any field. Its main purpose is to uniquely identify records in a table.

Practical: Creating a Student Table

After creating the database, we can create a table to store student information.

Suggested Table Structure

Field Name Suggested Data Type Purpose
Student_ID Integer Identifies the student
Name Text Stores student's name
Class Integer Stores class number
Section Text Stores section
Marks Decimal Stores marks

Steps to Create the Table

  1. Open the Tables section of the database.
  2. Choose the option for creating a table.
  3. Enter Student_ID as the first field name.
  4. Select a suitable numeric data type.
  5. Enter Name as another field.
  6. Select a suitable text data type.
  7. Add the Class field.
  8. Add the Section field.
  9. Add the Marks field.
  10. Set Student_ID as the primary key.
  11. Save the table.
  12. Give the table a meaningful name such as Students.
Precaution:
Choose field names and data types carefully before entering a large amount of data. Changing the structure later may affect existing data.

Editing and Deleting Records

Database information may need to be corrected or removed. For example, a student's marks may have been entered incorrectly or a student may have been removed from a particular list.

Editing a Record

  1. Open the required table.
  2. Locate the record that needs modification.
  3. Select the required field value.
  4. Replace the incorrect value with the correct value.
  5. Save the changes.

Deleting a Record

  1. Locate the record that is no longer required.
  2. Select the complete record.
  3. Choose the delete-record option.
  4. Confirm the deletion if prompted.
  5. Save the database.
Be Careful:
Deleting a record removes the complete record. Always verify the record before deleting it.

Editing the Structure of a Table

Sometimes we may need to modify the structure of an existing table. For example, we may need to add a new field such as Date_of_Birth.

Possible Structural Changes

  • Add a new field.
  • Change a field name.
  • Change a field's data type.
  • Remove a field when appropriate.
  • Modify field properties.
Important:
Structural changes should be made carefully. Changing or removing a field can affect the information already stored in the table.
